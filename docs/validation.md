# Validation locale — 27 octobre 2026

Environnement vérifié : Windows, Apache Lounge 2.4.69, PHP 8.5.5 Thread Safe, MySQL Community 8.4.13. PHP natif MVC, aucun framework runtime. Données de démonstration dans `sillage`, tests dans `sillage_test`.

- 73 contrôles des contrats métier et de la base MySQL : configuration de société, Unicode, domaines multiples, normalisation, refus des jokers et configurations ambiguës, restriction fermée par défaut et désactivation explicite, ancienne variable, identité de session par URL/port et clé ; domaine exact, nom proposé, hachage, dates, chiffrement, filtres, CSV, numérotation, parents, cycles, concurrence et agrégation ; heures décimales, valeurs invalides et absence distincte de zéro ; équipes, doublons, appartenance, rôles, désactivation, sessions et protection du dernier administrateur. Écritures unitaires annulées.
- 90 vérifications HTTP : session, CSRF, rendu des vues, fichiers privés, tickets et heures estimées, conflits, dates et tableau, filtres et exports, actions groupées, vues enregistrées, commentaires, pièces jointes, import CSV, webhooks signés, formulaire externe, archivage, inscription et récupération du compte ; création/renommage/suppression d’équipe, ajout/retrait, gestion des accès, fermeture de session et refus de connexion d’un compte désactivé.
- 28 vérifications HTTP supplémentaires sur deux configurations de société fictive : nom avec accent et esperluette échappé, domaines multiples, refus des sous-domaines et domaines ressemblants, inscription ouverte explicite, e-mails personnalisés, formulaires externes, menu et paramètres. La connexion et la récupération des comptes existants restent possibles après changement de domaine. Les trois profils de test utilisent la base isolée `sillage_test` et ne modifient pas l’installation locale principale.
- Vérification visuelle dans le navigateur : connexion, dashboard et thèmes clair/sombre. La couverture des gestes et des différents formats d’écran est détaillée par les vérifications ajoutées lors de la finition.
- Lanceur local réexécuté sur les données existantes : configuration conservée, migrations à jour, démonstration non dupliquée, serveur HTTP valide.
- Mode « base externe » exécuté avec la base locale existante comme point de connexion : Apache relancé, empreinte de `.env` inchangée, processus MySQL inchangés, aucune migration ni démonstration automatique. Aucune connexion à un hébergement externe ni connexion TLS réelle n’a été testée faute de paramètres fournis.
- Sauvegarde de la base locale par le script `bin/backup.php` : fichier SQL créé hors du DocumentRoot. La restauration et le retour arrière de production restent à vérifier sur le futur hébergement.

Une difficulté d’écriture/disparition de scripts CLI a été observée sur Windows pendant l’implémentation. Après demande de réessai, les scripts ont été restaurés et leurs tests relancés avec succès. Aucun réglage antivirus n’a été désactivé par l’agent.

Les tests de développement utilisent des fixtures signées et ne prouvent pas le fonctionnement réel de GitHub ou Bitbucket. Le relais mail réel, HTTPS, les sauvegardes/restaurations du serveur cible, le workflow SSH et les politiques GitHub de production nécessitent la configuration du propriétaire. Docker et les workflows distants n’ont pas été exécutés localement.
